# NotesToGo FactoryKit Migration — Requirements

## Goal
Replace the custom process-global Dependencies package with the installed FactoryKit library. Preserve service identity and app behavior while enabling isolated per-test service registrations and removing the duplicate repository-override injection path. This is a migration plan, not authorization to implement it or resume simulator tests.

## Scope
### In Scope
- Factory 3.5.0, already resolved in `notesToGo.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`; `FactoryKit` is linked to the app and `FactoryTesting` to unit tests.
- Migrate the two currently registered dependencies: `MyRouter` and `DocumentRepositoryProtocol`.
- Replace existing custom `@Dependency` consumers with Factory's eager `@Injected` or explicit composition-root resolution where initialization ordering requires it.
- Per-container service lifetimes, unit-test registrations, and parallel-test isolation.
- Debug-only UI-test repository configuration through Factory, replacing `repositoryOverride` and `EditorApp.build(repository:)` plumbing.
- Remove the custom package, keys, mode switching and unused imports after all consumers migrate.
- Preserve current uncommitted manual-save work and the user-installed Factory package changes. Keep the existing eight-slice persistence plan in root `REQUIREMENTS.md` unchanged.

### Out of Scope
- Implementing or redesigning manual Save, save-and-close, PDF export, drawing geometry or file-management behavior as part of this migration.
- Refactoring Flux, Router, view composition, feature state or navigation architecture.
- Registering every concrete object, view, feature store, pure value or temporary filesystem helper in a DI container.
- Replacing ordinary constructor injection such as `ExplorerMiddleware(explorer:)` or `Explorer`'s filesystem-operation collaborators merely for uniformity.
- Multi-scene containers, custom property wrappers, macros, generic service registries, container resets on normal app navigation, or changes to the upstream custom Dependencies repository.
- Running simulator tests until the user explicitly lifts the current pause.

## Requirements
- **R1 — One runtime DI mechanism:** Use FactoryKit for the app's router and editor document repository. Remove `DocumentMiddleware.repositoryOverride`, its optional repository constructor argument, the fallback lookup, and corresponding `EditorApp.build(repository:)`/app-startup parameter plumbing. Do not retain a second service-selection path disguised as a compatibility layer. Direct construction in focused repository/filesystem tests remains valid.
- **R2 — Explicit composition and lifetime:** Colocate simple factory registrations with their implementations: `Container.router` in `App/AppRouter.swift` and `Container.documentRepository` in `Modules/Editor/Infra/DocumentRepository.swift`. Do not keep a central `AppDependencies.swift` solely for these registrations. Keep launch-specific overrides in app startup and registrations out of render components. Use per-container `.cached` lifetimes for both factories: one router instance and one repository instance within a container; independent instances in different containers. Do not use process-global `.singleton`, weak `.shared`, or default transient scope for the router. Its root remains `.explorer(.dashboard(path: nil))`.
- **R3 — Shared navigation identity:** `AppContainer`, `EditorContainer`, `ExplorerContainer`, `SettingsContainer`, and `DocumentMiddleware` resolve the same router in one app container. Navigation initiated by middleware must affect the router rendered by `StackWithSheetRouterView`. Unit tests receive a fresh router rather than navigating the app host's router.
- **R4 — Register before resolving:** Factory's `@Injected` resolves at object construction, unlike the existing wrapper's dynamic reads. Register test/debug overrides before constructing their consumers, including middleware method references and feature stores. Do not expect changing a registration afterward to update existing consumers. Account for `@StateObject`'s deferred construction and property-wrapper initialization before an initializer body. Keep registration in the composition root, not SwiftUI `body`/`onAppear`.
- **R5 — Isolated unit tests:** Use `import FactoryTesting` and `@Suite(.container)` or `@Test(.container)` for DI-using Swift Testing tests. Create a fresh mock/failing/recording repository for each test, register it in that test's container, then construct the middleware/store. Avoid eagerly injected suite properties or global/static fixtures that resolve before registration. Remove `DependencyValues.setMode(.mock)`; do not replace it with a global `Container.shared.reset()` in setup/teardown. Prefer per-test construction helpers or a `.container { ... }` setup transform over relying on suite-initializer timing. Keep intentionally real-filesystem tests on real repositories.
- **R6 — Preserve async lifetimes:** Build and invoke test stores within their scoped container. Existing `Task { ... }` middleware dispatch must retain the intended service and router; an already constructed middleware must still use its injected instance when invoked later. Await middleware work before the test ends; do not introduce `Task.detached` or leaking background work. Review `FluxTestStore` teardown explicitly: unstructured tasks can retain a store beyond test completion, and a synchronous teardown wait on the main actor can block their progress; do not rely on suite `deinit` alone to drain effects. Add coverage for distinct interleaving test scopes and construction-time resolution.
- **R7 — Debug UI-test setup stays process-local:** The XCTest runner and app are separate processes; the runner's Factory container does not configure the app's container. Keep explicit launch-environment values and UUID-scoped temporary directories. In Debug app startup, validate the test ID and register a delayed/failing editor repository before constructing `EditorApp`/`DocumentMiddleware`. Normal Debug and Release launches use real repositories. Cleanup-only launches do not render normal navigation or seed test data.
- **R8 — Preserve creation behavior:** UI-test failure/delay injection applies only to the editor save path. Existing Explorer note creation and fixture seeding must continue to use their real creation/repository path; globally replacing all direct `DocumentRepository()` construction would consume fail-once behavior during creation and is not part of this migration. Preserve real filesystem failure injection used by `ExplorerMiddleware(explorer:)` tests.
- **R9 — Actor correctness:** Keep router and repository resolution consistent with their existing main-actor isolation and the project's Swift 6.2.1 toolchain. Annotate factories/consumers appropriately; do not silence errors with blanket `@unchecked Sendable`, `nonisolated(unsafe)`, or extra mutable global state. Factory's locking does not make a mutable service itself thread-safe.
- **R10 — Remove legacy integration:** After migrating consumers, remove `RouterKey`, `DocumentRepositoryKey`, custom `DependencyValues` extensions, all custom `import Dependencies`/`@Dependency` usage, global mode changes, and the custom Dependencies package/product from the Xcode project. Update package resolution without unrelated version upgrades. Keep FactoryKit on the app target and FactoryTesting on the unit-test target; do not add a separately linked FactoryKit copy to the test target. The installed Router package has no dependency on the old Dependencies package.
- **R11 — Verify behavior, not just compilation:** Add tests for per-container identity, distinct test containers, overrides taking effect before construction, later registration not silently rebinding an existing `@Injected` consumer, async save/failure/retry through registered services, shared router navigation, and real storage behavior. Remove `.serialized` only where it was compensating for shared DI state; inspect remaining shared state instead of claiming all suites can safely run in parallel.
- **R12 — Respect verification pause and working tree:** Planning changes documentation only. During implementation, preserve all current uncommitted slice-3/package work. Do not claim the current manual-save UI is already verified. Simulator execution, including hosted unit tests, requires renewed user authorization. After authorization, run unit and UI suites separately on iPad, plus a Release build; commit only agreed migration files after applicable checks are green, and do not push unless requested.

## Assumptions
- The installed Factory 3.5.0 checkout is the migration baseline. Its manifest requires Swift tools 6.1 and supports the current Swift 6.2.1 toolchain in principle; this has not yet been build-verified in this project.
- Per-container `.cached` preserves the old app-lifetime service identity without sharing mutable test services between `.container` test scopes. No additional lifetime configuration is needed for this app's present single-root architecture.
- The current slice-3 source changes are work in progress, not a verified baseline. Migration implementation must distinguish DI failures from outstanding manual-save behavior rather than silently broadening this task.
- The user wants a plan now. Factory installation does not authorize replacing production DI in this planning pass or restarting simulator tests.

## Implementation Plan
### 1. Register Container-Scoped Services
Description: Add actor-correct `router` and `documentRepository` factories beside their implementations using per-container `.cached` scope, initially without changing existing consumers. Add focused Factory lifetime tests proving repeated resolutions in one container share an instance and independent containers do not. Verify the app/test product wiring against the installed 3.5.0 APIs; retain existing package versions. This establishes the registrations used by subsequent slices without touching persistence behavior. Runtime checks await permission.

### 2. Migrate Consumers and Startup Overrides
Description: Depends on slice 1. Migrate router injection in `App/AppContainer.swift`, `Modules/Editor/App/EditorContainer.swift`, `Modules/Explorer/App/ExplorerContainer.swift`, `Modules/Settings/App/SettingsContainer.swift`, and `Modules/Editor/Middlewares/DocumentMiddleware.swift`. Migrate document-repository injection in `DocumentMiddleware` and remove `repositoryOverride` and repository parameter plumbing in `EditorApp.build`/app startup. Replace the existing Debug fixture return-and-pass pattern with a Factory registration before editor-store/middleware construction. Adapt directly affected test setup in the same change so existing tests do not continue configuring the old DI system. Verify native routing identity, construction order, real default storage, and editor-only delayed/failure injection. No new services or production behavior changes.

### 3. Isolate Tests and Prove Async Resolution
Description: Depends on slices 1–2. Finish converting `notesToGoTests/EditorTests.swift`, `OperationFailureTests.swift`, and `ManualSaveTests.swift` to per-test `.container` registration, including fresh mock instances and explicitly registered routers. Add focused interleaving-scope and initialization-order regressions; retain direct real repository tests in `DocumentStorageTests`/`StrictLoadingTests` and targeted constructor-injected Explorer tests. Await all async work and establish whether individual `.serialized` annotations remain necessary. Keep UI-test launch-environment/temporary-storage setup process-local and verify it still configures the app before resolution. Execute hosted tests only after the simulator pause is lifted.

### 4. Remove Legacy Package and Verify on iPad
Description: Depends on slices 1–3. Remove old keys/extensions, remaining custom imports/mode switching, and the old Dependencies package/product references; preserve the installed Factory products and unrelated user edits. Review source/project/package-resolution diffs for accidental upgrades and scan for obsolete override plumbing. Once authorized, build Debug/Release and run the full unit and UI suites separately on iPad; exercise normal launch, editor open/navigation, manual-save success/failure/retry, and test-directory cleanup. Record any unrelated slice-3 blockers rather than declaring success or committing an unverified migration. Document-only planning checks do not count as runtime verification.
